# CrossPad Applications

This directory contains all user-facing applications. On the board they are in MODE → More (pad 8); the simulator also shows them in its launcher.

## Fully Automatic App Registration System

The CrossPad application system uses **CMake code generation** to automatically discover and register apps. Simply create your app folder with a CMakeLists.txt and use the `REGISTER_APP` macro - no manual code changes needed anywhere else!

## Adding a New Application (3 Simple Steps)

### 1. Create App Directory & Files

```bash
main/app/
├── your_app/
│   ├── CMakeLists.txt
│   ├── your_app.cpp
│   └── your_app.hpp (optional)
```

### 2. Write CMakeLists.txt

```cmake
# Your App Module
# Paths are relative to main/ directory

set(YOUR_APP_SOURCES
    "app/your_app/your_app.cpp"
    # Add more source files as needed
)
# NOTE: Do NOT use PARENT_SCOPE here - the parent CMake will collect this automatically
```

**Variable naming:** Use `YOUR_APP_SOURCES` (uppercase) or `your_app_SOURCES` (lowercase). The parent CMake will auto-detect it.

### 3. Implement Your App with REGISTER_APP

In `your_app.cpp`:

```cpp
#include "your_app.hpp"
#include "crosspad/app/AppRegistrar.hpp"

// LVGL UI factory function
lv_obj_t * lv_CreateYourApp(lv_obj_t * parent, App * a) {
    // Create your LVGL UI here
    lv_obj_t * container = lv_obj_create(parent);
    // ... UI setup ...
    return container;
}

// Cleanup function. app is nullptr when the root was deleted elsewhere
// (a launcher rebuild): clean up, delete nothing.
void lv_YourApp_destroy(lv_obj_t * app) {
    // Clean up resources
    if (app) lv_obj_delete_async(app);
}

// REGISTER_APP macro - auto-registers your app at compile time
// Parameters: name, appLogic, icon, createFn, destroyFn,
//             initSimpleGUI, refreshGUI, cleanup, priority
REGISTER_APP(YourApp, nullptr, "/assets/your_icon.png",
             lv_CreateYourApp, lv_YourApp_destroy,
             nullptr, nullptr, nullptr, 50);
```

### That's It!

Run `idf.py build` and your app will:
- ✅ Be auto-discovered by CMake
- ✅ Have its sources compiled and linked
- ✅ Register itself via the `REGISTER_APP` macro
- ✅ Be in MODE → More (pad 8) on the board (the simulator also shows it in its launcher)

**No manual edits needed** to `main/app/CMakeLists.txt` or `main/gui/gui.cpp`!

## How It Works (Under the Hood)

### 1. Auto-Discovery (Configure Time)

`main/app/CMakeLists.txt` uses `file(GLOB)` to find all `*/CMakeLists.txt` files:

```cmake
file(GLOB APP_CMAKE_FILES "${CMAKE_CURRENT_LIST_DIR}/*/CMakeLists.txt")
foreach(app_cmake ${APP_CMAKE_FILES})
    get_filename_component(app_name ${app_dir} NAME)
    message(STATUS "Discovered app: ${app_name}")
    include(${app_cmake})

    # Auto-collect *_SOURCES variables
    if(DEFINED ${APP_NAME_UPPER}_SOURCES)
        list(APPEND APP_SOURCES ${${APP_NAME_UPPER}_SOURCES})
    # ... fallback patterns ...
endforeach()
```

### 2. Code Generation (Configure Time)

`main/app/CMakeLists.txt` calls `crosspad_generate_app_registry()` (crosspad-core `cmake/crosspad_app_registry.cmake`, shared with crosspad-pc), which scans all source files for `REGISTER_APP` macros and auto-generates `app_registry_init.cpp`:

```cpp
// Auto-generated file - DO NOT EDIT
// Generated by crosspad-core/cmake/crosspad_app_registry.cmake

extern void _register_YourApp_app();
extern void _register_AnotherApp_app();

void AppRegistry_InitAll() {
    _register_YourApp_app();
    _register_AnotherApp_app();
}
```

### 3. Registration (Runtime - Static Initialization)

Each `REGISTER_APP` macro expands to a registration function:

```cpp
void _register_YourApp_app() {
    static const AppRegistry::AppEntry entry = { /* ... */ };
    AppRegistry::getInstance().registerApp(entry);
}
```

The auto-generated `AppRegistry_InitAll()` is called during GUI initialization (in `main/gui/gui.cpp:InitializeAppRegistry()`), before the home screen (the MODE map) loads.

### 4. Linker Preservation

`main/CMakeLists.txt` uses `WHOLE_ARCHIVE` to ensure all app object files are linked, even if no external symbols are referenced:

```cmake
set_property(TARGET ${COMPONENT_LIB} PROPERTY WHOLE_ARCHIVE ON)
```

## REGISTER_APP Parameters

```cpp
REGISTER_APP(
    appName,        // App identifier (e.g., YourApp) - appears in logs
    appLogic,       // App logic function pointer (or nullptr for LVGL-only apps)
    iconPath,       // Icon path in LittleFS (e.g., "/assets/icon.png")
    createLVGL,     // LVGL factory: lv_obj_t* (*)(lv_obj_t* parent, App* a)
    destroyLVGL,    // LVGL cleanup: void (*)(lv_obj_t* app), app == nullptr when the root was deleted elsewhere
    initSimpleGUI,  // Simple GUI init function (nullptr if using LVGL)
    refreshGUI,     // Optional GUI refresh callback
    cleanup,        // Optional cleanup function
    priority        // Launch priority (higher = preferred, 0 = normal)
)
```

## Declarative Pad Logic (canonical)

Apps that own an `IPadLogicHandler` should declare it with `REGISTER_APP_PL`
instead of calling `setActivePadLogic()` manually:

```cpp
REGISTER_APP_PL(YourApp, nullptr, "/assets/icon.png",
                lv_CreateYourApp, lv_YourApp_destroy,
                nullptr, nullptr, nullptr, 0, "YourApp")
```

The last argument (`padLogicName`) names a handler the app registers via
`crosspad::getPadManager().registerPadLogic("YourApp", &handler)` inside its
create function. Activation is framework-owned: `AppBase::start()` pushes the
named logic and `destroyApp()` pops it — apps declaring `padLogicName` must
NOT call `setActivePadLogic()` themselves.

Apps without pad logic (or managing it manually) use plain `REGISTER_APP`.

See `crosspad-core/include/crosspad/app/AppRegistrar.hpp` for full macro definitions.

## Icon Assets

Place your app icon in `main/images/data/` - it will be packaged into the LittleFS `/assets/` partition at build time.

Supported formats: PNG, JPG. Recommended size: 64x64 px.

## Troubleshooting

### App doesn't appear in MODE → More

1. **Check CMake output:** Look for "Discovered app: your_app" in build log
2. **Check source collection:** Verify "Total app sources collected: ..." includes your files
3. **Check registration generation:** Look for "Generated app_registry_init.cpp with N apps"
4. **Check REGISTER_APP syntax:** Ensure macro is used correctly in your .cpp file
5. **Clean rebuild:** Try `idf.py fullclean` then `idf.py build`

### CMake doesn't find my app

- Ensure `main/app/your_app/CMakeLists.txt` exists
- Ensure variable name matches pattern: `YOUR_APP_SOURCES` or `your_app_SOURCES`
- Try `idf.py reconfigure` to force CMake re-scan

### App compiles but registration function not called

- Check `main/app/app_registry_init.cpp` was regenerated (it's auto-generated into `main/app/` at configure time and committed to git — never edit it manually)
- Verify `AppRegistry_InitAll()` is called in `main/gui/gui.cpp:InitializeAppRegistry()`
- Check device logs for "Initializing app registry" and "App registry initialized"

## App Registry System API

The application system provides:

- **AppRegistry** - Singleton that stores all registered apps
- **EventBus** - Cross-app communication (note events, pad events, tempo changes, etc.)
- **App** - Base class with LVGL integration and state management (in `crosspad-gui/app/App.hpp`)

See `crosspad-core/include/crosspad/app/` for registry API documentation.

## Community Contributions

This automatic registration system allows community developers to create and share CrossPad apps with zero modifications to core code. Just drop your app folder into `main/app/` and it works!

For app development guidelines and best practices, see [Create a new app](https://crosspad.app/docs/how-to/new-app/) and the "Creating a New App" section of the project's [CLAUDE.md](../../CLAUDE.md).
