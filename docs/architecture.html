Key Architectural Concepts

Portability via Interfaces

Apps depend on crosspad-core interfaces (IEventBus, IMidiOutput, ILedStrip, IClock) — never on platform specifics. The same app code runs on ESP-IDF and Arduino.

Singleton Factory Pattern

CrosspadPlatform_Init() creates 12 singletons in strict dependency order. All accessed via crosspad::getXxx() namespace functions.

Auto-Discovery Apps

Apps live in main/app/ as folders or git submodules. CMake auto-discovers them at configure time. REGISTER_APP macro + code generation handles registration.

Dual-Core FreeRTOS

Core 0: LVGL rendering (16ms tick). Core 1: event bus, pad animation (10ms), UART loop, app_main. Tasks communicate via EventBus queues.

Critical Warnings

✖
Never use static constructors — static AppRegistrar / __attribute__((constructor)) silently fail on ESP-IDF. Even with WHOLE_ARCHIVE, apps won't register. Always use the REGISTER_APP macro.
✔
Always run reconfigure — After adding a new app directory, idf.py reconfigure is required. A plain idf.py build will NOT re-run configure and the new app won't be discovered.
⚠
CMake variable scoping — In app CMakeLists.txt, use set(MY_APP_SOURCES ...) without PARENT_SCOPE. In the parent, aggregate with two separate set() calls.

Inter-Task Communication

EventBus Queue

64-entry FreeRTOS queue. UART task and PadManager post events. EventBus task dispatches to subscribers on Core 1. GUI subscribes via lv_async_call() for thread-safe LVGL updates.

LVGL Mutex

lvgl_port_lock() / lvgl_port_unlock() protect all LVGL API calls. LVGLTask holds the lock during lv_timer_handler(). Other tasks must acquire before touching UI objects.

Pad State

PadManager maintains pad colors and animation state. Animation task updates at 100Hz, writes to LED strip via RMT (non-blocking). Color changes are atomic uint32 writes.

MIDI Callbacks

UART loop parses MIDI from STM32 + USB. Callbacks fire on the UART task context. Heavy processing deferred to EventBus or PadManager for low-latency pad response.
